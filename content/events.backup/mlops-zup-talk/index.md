abstract: |
  Quase 90% dos projetos de Machine Learning falham antes de chegar à produção. Nesta talk, discuto o que muda quando trazemos dados para o ciclo de DevOps tradicional e por que o MLOps emergiu como disciplina própria — combinando engenharia de dados, machine learning e DevOps.

  Apresento os princípios fundamentais de MLOps adotados por grandes empresas de tecnologia, a diferença essencial entre DevOps e MLOps (a relação entre código e dados), e uma arquitetura de referência baseada em 5 blocos:

  1. **Ingestão de Dados** — pipelines ETL com Airflow, Data Lakes (S3, GCS, AWS Lake Formation)
  2. **Treinamento de Modelo** — escolha de hardware (CPU vs GPU) conforme a complexidade do algoritmo
  3. **Registro de Modelo** — versionamento e armazenamento de artefatos
  4. **Avaliação de Modelo** — garantia de métricas antes do deploy
  5. **Deploy / Model Serving** — implantação em produção

  O foco é dar a empresas com pouca maturidade em ML um caminho prático para uma arquitetura mínima, segura e escalável no contexto de produtos financeiros.
